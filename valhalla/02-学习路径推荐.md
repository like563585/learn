# 学习路径（推荐顺序）

## 📚 为什么要按这个顺序学习？

Valhalla 是一个复杂的系统，但它的各个模块之间有明确的依赖关系。按照这个顺序学习能够：
- ✅ 建立清晰的概念基础
- ✅ 避免"看代码一头雾水"的情况
- ✅ 理解设计权衡（为什么这样而不是那样）
- ✅ 快速定位问题、做出修改

---

## 第1阶段：基础数据结构（必读）⭐⭐⭐

**为什么先学这个？** 这是整个系统的基石。不懂数据结构，后续逻辑无法理解。

### 1.1 Midgard - 几何基础

Valhalla 中所有地理计算都基于这些基本类。

**核心文件：**
- `valhalla/midgard/point2.h` — 2D 点、向量、距离计算
- `valhalla/midgard/pointll.h` — 地球坐标（经纬度）、大圆距离
- `valhalla/midgard/polyline.h` — 折线编码/解码（Google 算法）
- `valhalla/midgard/vector2.h` — 向量运算

**学习重点：**
```cpp
// PointLL 对象很轻（只有 2 个 double）
PointLL beijing(116.4074, 39.9042);   // 北京
PointLL shanghai(121.4737, 31.2304);  // 上海

// 计算大圆距离（球面）
float dist = beijing.Distance(shanghai);  // ~1063 km

// 投影到平面（用于快速计算）
Point2 p = beijing.Project();
```

**关键问题：**
- 为什么需要既有 PointLL 又有 Point2？
- 大圆距离和欧氏距离的差异在哪？
- 为什么 polyline 编码要保留 6 位小数？

**学习时间：** 1-2 小时

---

### 1.2 Baldr - 图的数据结构

这是 Valhalla 最聪明的地方：用 40 字节紧凑表示一条有向边。

**核心文件：**
- `valhalla/baldr/directededge.h` — **最关键**，有向边
- `valhalla/baldr/nodeinfo.h` — 节点信息
- `valhalla/baldr/edge_info.h` — 边的详细信息
- `valhalla/baldr/graphtile.h` — 瓦片格式、内存映射

**学习重点：**

```cpp
// DirectedEdge (40 bytes) 结构
// 紧凑到位域级别，为什么？
class DirectedEdge {
    uint32_t way_index_ : 24;        // 指向 EdgeInfo 表
    uint32_t tile_info_ : 8;         // 邻居瓦片信息
    uint32_t forward_ : 1;           // 正向/反向
    uint32_t internal_ : 1;          // 瓦片内/跨瓦片
    uint32_t toll_ : 1;              // 收费
    uint32_t unpaved_ : 1;           // 未铺装
    // ... 还有4个空闲位等待未来功能
};

// GraphTile 是二进制文件中的一个块
// 支持内存映射，查询零开销
class GraphTile {
    // 固定大小的头部
    // NodeInfo[] 数组
    // DirectedEdge[] 数组
    // EdgeInfo[] 数组
};
```

**关键问题：**
- DirectedEdge 为什么要用位域？内存节省了多少？
- way_index 只有 24 位，意味着什么限制？
- 为什么把 GraphTile 设计成固定大小？
- 内存映射相比传统加载有什么优势？

**代码学习：**
```bash
# 查看实现细节
less src/baldr/directededge.cc
less src/baldr/graphtile.cc

# 理解位域布局
grep -A 20 "class DirectedEdge" valhalla/baldr/directededge.h
```

**学习时间：** 2-3 小时

## 第2阶段：成本模型（核心逻辑）⭐⭐⭐

**为什么学这个？** 决定了路由结果的质量。同一条路在不同交通方式下成本不同。这是定制路由的关键。

### 2.1 Sif - 动态成本模型

**核心文件：**
- `valhalla/sif/dynamiccost.h` — 基类，定义成本计算接口
- `valhalla/sif/autocost.h` — 汽车成本（速度限制、禁行）
- `valhalla/sif/bicyclecost.h` — 自行车成本（坡度、路面）
- `valhalla/sif/pedestriancost.h` — 行人成本（人行道、楼梯）
- `valhalla/sif/transitcost.h` — 公共交通成本

**学习重点：**

```cpp
// 虚基类定义接口
class DynamicCost {
    // 边的成本（时间或距离）
    virtual Cost EdgeCost(const DirectedEdge* edge) = 0;
    
    // 转向成本（转向角度、等待时间）
    virtual Cost TransitionCost(const DirectedEdge* prev,
                                 const DirectedEdge* curr) = 0;
    
    // 通行性检查（禁行、单行）
    virtual bool Allowed(const DirectedEdge* edge) = 0;
};

// AutoCost 实现示例
class AutoCost : public DynamicCost {
    // 汽车速度通常由道路类型 + 速度标记决定
    Cost EdgeCost(const DirectedEdge* edge) {
        // 根据 highway tag (motorway/trunk/primary...)
        // 根据 speed limit tag
        // 是否有收费？
        return time_cost;
    }
    
    // 右转通常比直行快，左转比右转慢
    Cost TransitionCost(...) { ... }
};
```

**关键问题：**
- 为什么有时候绕远路成本反而低？（高速公路 vs 城市街道）
- 转向成本怎么计算？U 形转弯和右转转向成本一样吗？
- 如何处理收费、禁行、单行道？
- 为什么自行车路线会避开某些道路？

**对比学习：**
```bash
# 对比三种成本模型
diff -u valhalla/sif/autocost.h valhalla/sif/bicyclecost.h
# 看看自行车对哪些因素更敏感

# 查看坡度影响
grep -A 10 "grade" src/sif/bicyclecost.cc
```

**学习时间：** 2-3 小时

## 第3阶段：寻路算法（Thor）⭐⭐⭐

**为什么学这个？** 双向 A* 是路由的心脏。理解它才能优化性能。

### 3.1 Thor - 寻路引擎

**核心文件：**
- `valhalla/thor/bidirectional_astar.h` — **双向 A\* 的核心**
- `valhalla/thor/pathinfo.h` — 路径节点存储
- `src/thor/bidirectional_astar.cc` — 实现细节

**学习重点：**

```cpp
// 双向 A* 的基本思想
class BidirectionalAStar {
    // 从起点和终点同时出发
    // 当两个方向在中间相遇时，找到最短路
    
    std::vector<PathInfo> GetBestPath(
        const PointLL& origin,
        const PointLL& destination,
        const DynamicCost* costing) {
        
        // 1. 初始化两个优先队列 (forward & reverse)
        // 2. 交替扩展两个方向
        // 3. 检查对称性（从两边各有一条到相同节点的路径）
        // 4. 重构路径
    }
    
private:
    // 启发式函数 (heuristic)
    // 估计节点到目标的距离
    float GetHeuristic(const PointLL& node, 
                       const PointLL& target);
};
```

**关键概念：**
- **启发式函数**：用什么估计距离？欧氏距离还是大圆距离？
- **对称性检查**：为什么需要检查？
- **分层图**：Valhalla 用分层图加速（高速公路 > 干道 > 小街道）
- **剪枝**：如何避免搜索不必要的节点？

**问题导向：**
- 为什么不用 Dijkstra？（启发式能加速）
- 为什么要双向？（减少搜索节点）
- 启发式不准确会怎样？（可能找不到最优路）

**学习时间：** 3-4 小时

## 第4阶段：位置关联（Loki）⭐⭐

**为什么学这个？** GPS 坐标（可能有误）必须关联到真实道路边。直接影响路由起点。

### 4.1 Loki - 位置搜索

**核心文件：**
- `valhalla/loki/search.h` — 坐标→最近边的搜索
- `valhalla/loki/isochrone.h` — 等时线算法
- `src/loki/search.cc` — 搜索实现

**学习重点：**

```cpp
// 给定 GPS 坐标，找最近的道路边
class Search {
    // 在瓦片中查找最近边
    PathLocation SearchNearestEdge(const PointLL& location);
    
    // 可能有多条边同样接近
    std::vector<PathLocation> SearchNearestEdges(
        const PointLL& location, 
        int max_results);
};

// 等时线：计算从一点出发，在 N 分钟内能到达的区域
std::vector<PointLL> IsochroneContour(
    const PointLL& center,
    uint32_t time_limit_seconds);
```

**关键问题：**
- GPS 误差 5-10m，怎么保证吸附到正确的道路边？
- 为什么需要多个候选边？
- 等时线怎么计算（暴力搜索所有节点？）

**学习时间：** 2-3 小时

## 第5阶段：转向指令生成（Odin）⭐⭐

**为什么学这个？** 把原始路径转换成"向右转入 Main St"这样的人类可读指令。

### 5.1 Odin - 叙述生成

**核心文件：**
- `valhalla/odin/maneuver.h` — 转向类型定义
- `valhalla/odin/directionsbuilder.h` — 如何从边序列生成转向
- `src/odin/directionsbuilder.cc` — 实现

**学习重点：**

```cpp
// 转向类型枚举（几十种）
enum class ManeuverType : uint8_t {
    kStart,           // 启程
    kTurn,            // 转向
    kContinue,        // 直行
    kBecomeRamp,      // 变成匝道
    kMerge,           // 并线
    kKeepLeft,        // 靠左保持
    kKeepRight,       // 靠右保持
    // ...
};

// 生成转向指令
class DirectionsBuilder {
    // 输入：PathInfo 数组（边序列）
    // 输出：Maneuver 数组（转向指令）
    std::vector<Maneuver> Build(
        const std::vector<PathInfo>& path);
};
```

**关键问题：**
- 如何检测"继续直行"vs"保持车道"？
- 右转 vs 向右合并有何区别？
- 如何生成多语言的转向文本？
- 街道名称怎么从 OSM 数据中提取？

**学习时间：** 1-2 小时

## 第6阶段：图的构建（Mjolnir）— 可选 🟢

**为什么可选？** 除非你要修改 OSM 数据处理，否则可以先跳过。但了解构建过程能帮助理解数据格式。

### 6.1 Mjolnir - 离线瓦片生成

**核心文件：**
- `valhalla/mjolnir/graphbuilder.h` — 图构建主逻辑
- `src/mjolnir/osmdata.cc` — 如何解析 OSM PBF 文件
- `lua/` — Lua 脚本定义道路标签优先级

**学习重点：**

```cpp
// 从 OSM PBF 文件构建图瓦片
class GraphBuilder {
    // 1. 解析 OSM (节点、路、关系)
    // 2. 分类道路 (motorway/trunk/primary...)
    // 3. 分配瓦片坐标
    // 4. 构建边的连接性
    // 5. 添加元数据 (名称、收费、禁行等)
    // 6. 序列化为二进制瓦片
};

// Lua 脚本例子: 按道路优先级排序
-- 在 lua/ 文件中定义
if highway == "motorway" then
    priority = 10
elseif highway == "trunk" then
    priority = 9
elseif highway == "primary" then
    priority = 8
```

**学习时间：** 4-6 小时（可选）

## 💡 学习技巧

### 技巧1：先读头文件（.h）不要看实现（.cc）

```bash
# ✅ 正确做法
cat valhalla/sif/dynamiccost.h  # 先了解接口

# ❌ 错误做法
cat src/sif/autocost.cc         # 上来就看实现
```

**理由：** 头文件是"API 契约"，先理解接口的设计意图，再钻研实现细节。

### 技巧2：用 UML 图描述模块关系

```
HTTP 请求
  ↓
[Tyr] 协调层
  ├─→ [Loki] 坐标吸附
  ├─→ [Sif] 成本模型
  ├─→ [Thor] 寻路

  ↓

```

## 🚀 后续方向

- **想优化路由速度？** → 深入 Thor 的启发式函数和剪枝策略
- **想添加新的交通方式？** → 在 Sif 中实现新的 DynamicCost 子类
- **想改进转向指令？** → 学习 Odin 的语言本地化和上下文分析
- **想处理实时交通？** → 了解 traffic_element_t 结构和动态成本调整
- **想支持共享单车/电动车？** → 创建 SharedBikeCost 或 ScooterCost 类
- **想改进地图匹配？** → 研究 Meili 的 Viterbi 算法和HMM 隐马模型

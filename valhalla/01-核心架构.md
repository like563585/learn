# 核心架构与模块说明

## 路由请求流程图

```
HTTP 请求 → Tyr (服务层)
           ↓
       Loki (位置关联) → 将坐标吸附到道路边
           ↓
       Thor (寻路) → 通过图层级寻找路径
           ↓
       Odin (叙述生成) → 转向指令 + 导航文本
           ↓
       返回 JSON 响应
```

## 数据流示例

### 1. 构建阶段 (离线)

```
OSM PBF 文件 (来自 OpenStreetMap)
    ↓
[Mjolnir] 解析 → 标签处理 (Lua)
    ↓
[Mjolnir] 构建道路图 → 分配瓦片坐标
    ↓
[Mjolnir] 添加高程、时区、行政边界数据
    ↓
二进制瓦片文件 (.tar) ← 缓存在磁盘
```

### 2. 查询阶段 (在线)

```
HTTP /route 请求: {"locations": [...], "costing": "auto"}
    ↓
[Tyr] 解析请求 → 创建 Actor
    ↓
[Loki] 加载瓦片 → 坐标吸附到边
    ↓
[Sif] 创建成本模型 (AutoCost)
    ↓
[Thor] 双向 A* 寻路
    ↓
[Odin] 生成转向指令 + 多语言文本
    ↓
JSON 响应 + Protobuf 序列化
```

## 核心概念速览

### DirectedEdge（有向边）

```cpp
// 40 字节，紧凑二进制格式
struct DirectedEdge {
    uint32_t way_index : 24;      // 指向 EdgeInfo 表
    uint32_t tile_info : 8;       // 邻居瓦片信息
    uint32_t forward : 1;         // 正向/反向
    uint32_t internal : 1;        // 瓦片内/跨瓦片
    // ... 还有4个空闲位留给未来功能
};
```

**为什么要这样设计？**
- 内存效率：百万级边需要紧凑存储
- 速度：缓存友好（< L1 缓存行）
- 限制：只有24位给 way_index，最多 16M 条边/瓦片

### GraphTile（瓦片）

```
固定大小的二进制块 (通常 64KB)
├─ Header
│  ├─ 版本号
│  ├─ 节点数、边数、边信息数
│  └─ 相邻瓦片 ID
├─ NodeInfo[] 数组 (节点信息)
├─ DirectedEdge[] 数组 (出边)
└─ EdgeInfo[] 数组 (边详细信息)

特点: 预编译 & 内存映射，查询零开销
```

### PointLL（地球坐标）

```cpp
// 地理坐标系统
struct PointLL {
    double lat, lng;  // 纬度、经度
    
    // 大圆距离 (球面)
    float Distance(const PointLL& p);
    
    // 投影到方格纬度 (平面近似)
    Point2 Project() const;
};
```
